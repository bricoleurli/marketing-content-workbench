# 素材上传与存储

当前版本使用服务器文件系统，尚未实现 COS 读写。GitHub 仅保存代码。

- 图片：叠加模板 → 新建模板 → 批量上传图片（JPEG、PNG、WebP）。
- 视频：事件镜头 → 选择或创建事件分组 → 从 Cap 导入；该入口接受普通 MP4，不要求一定由 Cap 制作。
- 当前 HTTPS 入口每个请求上限 100 MiB；图片批次的 JSON 请求上限 80 MiB（包含 base64 膨胀）。大视频先压缩或通过受控批量迁移。
- 素材总览是聚合展示入口，不是通用文件上传页。已有配音没有独立批量导入界面。
- 共享体验站没有用户隔离，上传文件与模板可被其他访问者看到、修改。不要将私人素材整库迁入此实例。

## 保留本地旧库

一次性迁移应复制数据及索引，而非只复制视频：

| 数据 | 新部署数据目录下的位置 |
| --- | --- |
| 事件库（包括 events、voices 和说明文件） | event-library/ |
| 叠加模板（包括 instances、图片和参数） | overlays/ |
| 配音导出 | outputs/ |

先清点来源、备份目标，再复制到暂存目录，核对文件数量及校验和，设置服务账号权限，最后切换数据路径并验证。已有目标内容时不能直接覆盖同名条目。音色和密钥只在用户明确要求时单独迁移至 `config/settings.json`，权限设为 600，绝不能提交 Git。配音历史须同步 `config/history.json`，核对其中的文件存在，音频 URL 应为站内 `/outputs/` 路径。

## 后续接入 COS

建议采用私有桶、独立前缀、服务器端最小权限身份及短期签名地址。
浏览器通过受限上传凭证直接传文件到 COS；服务器保存素材 ID、对象键、分组与模板参数。
导出时服务器把所需图片下载到本地缓存、执行渲染，再把成品存到 COS。
同参数同素材命中已有成品时直接提供签名下载链接。

COS 负责容量、下载带宽和持久保存，不代替 CPU 渲染；服务器仍承担生成视频的计算。
接入需要新增存储适配、上传授权、读取缓存及成品回存代码，仅把文件放进桶里不能让当前程序自动识别。

## 共享内容站的读取配置

匿名空体验站使用 `deploy/nginx-trial.conf`，它会返回空选题、空音色和空历史。用户明确要求展示已同步内容时，使用 `deploy/nginx-shared-content.conf`，并替换域名和证书路径。该配置通过应用读取数据目录中的 `topics-data.js`、音色及配音历史；所有访问者都能看到这些内容。

`/api/config` 仅返回密钥是否配置，不返回密钥值。两个配置均禁止公网修改全局设置和调用付费生成。先备份现有 Nginx 配置，运行 `nginx -t` 成功后 reload；代码发布不会自动替换 Nginx 配置。
